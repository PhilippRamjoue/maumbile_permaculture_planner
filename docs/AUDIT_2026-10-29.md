# Code audit — 2026-10-29

A deep pass over the whole codebase (backend + frontend) looking for technical debt, dead/unused
code, architectural smells and error-prone patterns, after several rapid rounds of editor feedback.

## Verdict

**The codebase is healthy and disciplined.** Module boundaries are clean, the frontend is strictly
typed, there are **zero** `TODO`/`FIXME`/`HACK` markers, and test depth is strong (frontend ≈245
tests, backend 241 + PostGIS integration). The findings below are **refinements for long-term
maintainability, not rescue work.** Two are structural (the editor god-component); most are cheap
guardrails that stop debt from accumulating as the project grows.

## What is already strong (keep doing)

- **Backend boundaries are exemplary.** Verified by grep: **no** `service.py` imports FastAPI or a
  router; nearly every `repository`/`models` import is same-module. The one cross-module path
  (`planning → sites`) goes through `SiteService` (a service interface) at the DI composition root,
  exactly as the architecture prescribes (`router → service → repository`).
- **Region-as-data design holds.** Adding a provider is "adapter + seed row", no core change —
  proven twice this week (imagery providers), and the resolver/profile tests are self-contained.
- **Frontend typing is strict** (`strict` + `noUnusedLocals` + `noUnusedParameters`); essentially
  zero type escapes (`as any`/`@ts-ignore`). The 32 backend `# type: ignore`/`# noqa` are all
  legitimate (FastAPI handler typing, Alembic model imports, the intentional `format` query param).
- **Generated API contracts** for imagery with a CI drift check.

## Findings (prioritized)

### P1 — Structural (highest leverage, highest touch)

1. **`Workspace.tsx` is a god-component — 895 lines, 19 `useState`, 5 `useEffect`, 49 hook-derived
   values.** Every editor concern funnels through it: tool/layer/selection state, imagery + basemap
   choice, sector-kind, save/autosave/dirty/navigation-blocker, boundary editing, and the whole
   control bar. This is why a single change (e.g. lifting sector-kind) had to touch Workspace,
   `useEditorMap`, the panel and the helper together — the blast radius is large.
   - **Recommend:** extract cohesive custom hooks, one per PR, leaning on the existing tests as the
     net: `useImageryBasemap(siteId)` (providers + choice + effective provider),
     `useSectorAdding()`, `useEditorPersistence()` (save/autosave/dirty/blocker), `useActiveLayer()`
     (tool→layer routing), plus a `<MapControlBar>` sub-component. Target orchestration < ~300 lines.

2. **`useEditorMap.ts` — 520 lines built around one mega-`useEffect`** that assembles sources,
   layers, paint, interaction handlers and Terra Draw wiring, with a broad dependency array (any
   change rebuilds everything, e.g. a tool switch re-adds imagery layers).
   - **Recommend:** move the pure layer/paint builders out (some already live in `focus/view.ts`)
     and split the effect by concern (imagery source vs design layers vs interactions). Cuts
     needless rebuilds and cognitive load.

### P2 — Guardrails (cheap; make the good habits self-enforcing)

3. **15 phantom (unlisted) frontend dependencies.** `geojson`/`@types/geojson`, `@turf/distance`,
   `@maplibre/maplibre-gl-style-spec` are imported but **not declared** in `package.json` — they
   resolve only transitively (via maplibre/turf). A transitive bump that drops or relocates them
   silently breaks the build. **Fix:** declare them explicitly (deps/devDeps). One-liner, removes a
   latent build break.

4. **mypy is not strict** — only `check_untyped_defs`. An untyped function or an accidental `Any`
   return slips through as the backend grows. **Recommend:** enable incrementally
   (`disallow_untyped_defs`, `disallow_incomplete_defs`, `warn_return_any`, `no_implicit_reexport`,
   or `strict = true`), fixing fallout module by module. Locks in the discipline the code already
   mostly follows.

5. **The module-boundary rule isn't machine-enforced.** It's clean today, but nothing stops a future
   `from app.modules.x.repository import …` inside another module's service. **Recommend:** a ruff
   `flake8-tidy-imports` banned-api (TID251) rule or an `import-linter` contract that fails CI on
   cross-module `repository`/`models` imports. Makes the architecture self-policing.

6. **No unused-code gate.** `knip` found 2 dead files, 43 unused exports, 16 unused types today;
   these accumulate silently. **Recommend:** add `knip` to CI (or a pre-release check). Optionally
   `vulture` with a whitelist for the backend (noisy on FastAPI/ORM, so whitelist-based).

### P3 — Cleanup (low-risk; do opportunistically)

7. **`localStorage` try/catch is duplicated across 7 files** (`BasemapSwitcher`, `LayersControl`,
   `MapLegend`, `imageryChoice`, `TerrainControl`, `focus/editorLevelStore`, `focus/modes`).
   **Recommend:** a `shared/` `safeLocalStorage` (get/set swallowing errors) or a
   `usePersistentState(key, default)` hook. DRY, and no path can forget the private-mode guard.

8. **Dead/loose frontend exports (from `knip`):** delete the 2 unused barrel files
   (`features/map/index.ts`, `features/site-setup/index.ts`); de-export or delete the 43 unused
   exports and 16 unused exported types (knip already accounts for test usage, so these are truly
   unreferenced — still verify before deleting); collapse the duplicate
   `IMAGERY_MAX_ZOOM`/`MAX_FIT_ZOOM` export in `map/layers/zoomLimits.ts` to one name.

9. **Backend version drift.** `backend/pyproject.toml` and `app/main.py` are pinned at `0.1.0` while
   the app ships 0.4.x, so the FastAPI OpenAPI docs advertise `version="0.1.0"`. **Recommend:** bump
   them on release, or derive the FastAPI `version` from the same single source the frontend footer
   uses (the release tag / an env var).

### P4 — Process (from today's incident)

10. **Run the *full* suite before tagging a release.** The 0.4.0 build failed only at the CI gate
    because a top-level `backend/tests/regions/` assertion (outside `app/modules/*/tests/`) wasn't
    run locally before tagging. **Recommend:** a one-command local "release preflight" that runs the
    exact CI set — `uv run pytest` (whole suite), `npm test`, both typechecks, `generate_frontend_contracts --check`
    — rather than module-scoped subsets. The gate correctly caught it; this just avoids a dead tag.

## Suggested order

1. **P2 guardrails first** — they're cheap and stop the bleeding: declare the phantom deps (#3), add
   the import-boundary lint (#5), add `knip` to CI (#6), and start the mypy-strict ramp (#4).
2. **P3 cleanup** (#7–9) opportunistically — each is small and self-contained.
3. **P1 refactors** (#1–2) deliberately, one hook/sub-component per PR, with the existing tests as
   the safety net. This is the real long-term win, and the highest-touch, so it's last.

Nothing here is urgent or risky; the architecture is sound. These steps mostly make the existing
discipline automatic so it survives future rapid-iteration rounds.
